# CCTV 화분·야구방망이 탐지

`YOLO12n` `Python` · 2026.07(1일) · 데이터 수집부터 운영 연동까지 담당

![탐지 예시](docs/detection-example.jpg)

<sub>배포 카메라 영상 중 학습에 쓰지 않은 구간에 모델을 돌린 결과입니다. 사람이 드러나지 않도록 탐지된 물체 칸 밖은 흐리게, 사람 머리 근처는 한 번 더 흐리게 처리했습니다.</sub>

CCTV에서 화분과 야구방망이를 잡는 2클래스 경량 탐지 모델(YOLO12n, 5.3MB)입니다.
운영 시스템에 비어 있던 2차 모델 슬롯에 연결해서, 운영 코드는 고치지 않고 올렸습니다.
앞서 걷기·서기 판정을 하면서 정리해 둔 학습 방식과 평가 방법을 그대로 가져와 하루 만에 끝냈습니다.

- 방망이를 놓치는 비율 44% → 14%
- 범용 탐지 성능은 떨어지지 않음 (0.561 → 0.565)
- 측정은 학습에 쓰지 않은 배포 카메라 영상 380프레임(방망이 274박스)

사내 프로젝트라 소스 코드와 데이터는 공개하지 않습니다.

## 성능

| | 1차 배포 | 최종 | 변화 |
|---|---|---|---|
| 방망이 AP50 | 0.597 | 0.852 | +0.255 |
| 방망이 재현율 | 0.558 | 0.861 | +0.303 |
| 방망이 정밀도 | 0.652 | 0.829 | +0.177 |
| 범용 탐지 성능 | 0.561 | 0.565 | +0.004 |

운영 조건으로 재면 방망이가 보이는 3초 구간을 놓치지 않을 확률이 99.7%이고, 방망이가 없는 영상에서 잘못 잡는 빈도는 분당 0.95프레임입니다.

범용 탐지 성능 0.565는 낮아 보이지만, 원래 사전학습 모델도 같은 조건에서 0.535가 나옵니다. 조건 자체가 어려운 영상이었고, 기준선을 먼저 재 보고 나서야 이 숫자가 떨어진 게 아니라는 걸 알 수 있었습니다.

## 만들면서 있었던 일

먼저 쓸 수 있는 공개 데이터가 얼마나 되는지 셌습니다. 화분은 충분했지만 방망이는 거의 없었습니다. 공개 데이터의 방망이는 대부분 야구 경기 장면이라, CCTV 속에서 사람이 들고 있는 모습과는 달랐습니다. 화분을 더 모으면 클래스 불균형만 커져서 화분 수집은 거기서 멈췄습니다.

라벨링은 큰 모델로 초안을 뽑고 제가 검수하는 방식으로 했습니다. 그 전에 대형 모델의 방망이 탐지율이 58–70%로 경량 모델(12–29%)보다 충분히 높은지 먼저 재서, 초안으로 쓸 만한지 확인했습니다. 대형 모델은 라벨링에만 쓰고 배포하지는 않았습니다.

1차 배포 모델은 평가 때 AP50이 0.897이었는데, 배포 카메라에서는 0.597이었습니다. 평가셋이 학습에 쓴 영상의 뒷부분이었기 때문입니다. 그 뒤로는 학습에 오후 3시대, 검증에 오후 1시대 영상을 써서 같은 카메라라도 다른 시간대로 나눴습니다. 이렇게 나눠 둬서 최종 0.852가 실제로 나아진 값이라고 말할 수 있었습니다.

최종 모델을 고를 때는 선정 스크립트의 결과를 따르지 않았습니다. 스크립트는 AP50이 가장 높은 안을 골랐지만, 두 안의 AP50 차이는 0.001이었고 재현율 차이는 0.087이었습니다. 보안 용도에서는 놓치는 쪽이 잘못 잡는 쪽보다 문제가 크다고 봐서 재현율이 높은 안을 골랐습니다.

성능을 가장 많이 올린 건 배포 카메라에서 나온 데이터였습니다. 운영 서버가 이미 1분 단위로 쌓아 두던 원본 영상을 학습에 넣은 것이 개선의 대부분을 차지했습니다.

## 한계

- 바닥에 놓여 있는 방망이는 잘 못 잡습니다. 학습 데이터의 방망이가 전부 사람과 함께 찍혀 있어서, 모델이 "사람 손 근처의 긴 막대"를 배웠습니다. 사람 없이 방망이만 두고 1~2분 찍으면 해결할 수 있는 문제라는 것까지 확인했습니다.
- 카메라 1대에서만 검증했습니다.
