# CCTV 걷기·서기 판정

`YOLO` `Python` · 2026.07(약 26일) · 데이터 수집부터 운영 연동까지 담당

운영 중인 CCTV 관제 시스템에서 사람이 걷고 있는지 서 있는지 판정하는 기능입니다.
처음에는 전용 분류 모델을 만들어 배포했는데, 측정을 다시 해 보고 그 모델을 빼기로 했습니다.
지금은 기존 흉기 탐지 모델이 이미 잡아 둔 사람 박스가 프레임 사이에 얼마나 움직였는지로 판정합니다.

- 균형 정확도 75.5% (아무 판단도 하지 않는 기준선은 50%)
- 전용 모델을 빼서 추가 연산 0
- 정답 데이터는 직접 검수한 2,818박스 (16개 클립, 171구간)
- 기존 흉기 탐지는 건드리지 않고 확장 슬롯과 읽기 전용 경로만 사용

사내 프로젝트라 소스 코드와 데이터는 공개하지 않습니다.

## 성능

| 설정 | 정확도 | 균형 정확도 | 서기 | 걷기 |
|---|---|---|---|---|
| 운영값 | 72.2% | 75.5% | 82.5% | 68.5% |
| 기준선: 전부 "걷기"로 답하기 | 73.6% | 50.0% | 0% | 100% |

정답의 73.6%가 걷기여서, 전부 "걷기"라고 답해도 정확도는 운영값보다 높게 나옵니다.
그래서 두 클래스를 같은 무게로 보는 균형 정확도를 기준으로 봤습니다.

## 학습 때 점수와 실제가 달랐던 일

![학습 때의 평가 결과](docs/confusion-matrix-training.png)

<sub>전용 모델을 학습할 때 나온 평가 결과입니다. 서기 96%, 걷기 97%로 보였지만 아래 이유로 부풀려진 점수였습니다.</sub>

처음에는 사람 이미지를 잘라서 자세로 분류하는 방식을 세 가지 구조로 시도했습니다. 마지막 구조는 검증 정확도가 100%였는데, 새 영상에 돌려 보니 걷는 사람의 90%를 놓쳤습니다. 데이터에서 걷기는 야외, 서기는 실내에서 찍힌 것이라 모델이 자세 대신 배경을 배운 것이었습니다. 따져 보니 사진 한 장으로는 애초에 걷기와 서기를 가를 수 없었습니다. 걷는 도중의 한 순간과 서 있는 자세가 한 장에서는 똑같이 보이기 때문입니다. 그래서 프레임 사이의 움직임을 보는 구조로 바꿨습니다.

두 번째는 mAP 0.98이 나온 모델이었습니다. 학습셋과 평가셋이 같은 영상에서 몇 초 간격으로 잘라 낸 프레임이라, 사실상 같은 장면으로 채점하고 있었습니다. 라이브 영상으로 다시 재니 서기 재현율이 96%에서 31%로 떨어졌습니다.

## 전용 모델을 뺀 이유

후처리 값을 조정해서 맞춰 보다가 더 나아지지 않아 구조를 다시 봤습니다. 최종 판정은 이미 박스 이동량으로 하고 있었고, 전용 모델이 실제로 하는 일은 사람 박스를 넘겨주는 것뿐이었습니다. 그런데 같은 프레임을 기존 흉기 탐지 모델도 처리하고 있었고, 사람은 그쪽이 더 잘 잡았습니다. 같은 영상에서 기존 모델은 사람 박스 226개를 잡았는데 전용 모델은 71개였고, 창가에 서 있는 사람은 아예 잡지 못했습니다.

전용 모델을 빼고 기존 모델의 사람 박스를 쓰도록 바꾸자 판정이 한쪽으로 쏠리던 것이 없어지고 추적도 안정됐습니다. GPU 부하가 줄었고 재학습할 일도 없어졌습니다.

## 평가 방법

같은 판정을 세 단계로 나눠서 쟀습니다. 최종 결과만 보면 어디서 틀렸는지 알 수 없어서입니다.

| 단계 | 재는 것 |
|---|---|
| 프레임 | 모델이 사람을 제대로 잡는가 |
| 이동량 | 판정 로직이 걷기와 서기를 맞게 가르는가 |
| 최종 출력 | 스무딩과 상태 전이를 거친 뒤 사용자가 보는 결과 |

추적을 시작한 직후 약 0.5초 동안이나, 너무 작아서 앉은 사람과 구분되지 않는 박스는 억지로 판정하지 않고 "사람"으로만 표시합니다.

## 한계

- 카메라 1대에서만 검증했고, 다른 각도·조도·배치에서는 재 보지 않았습니다.
- 사람 박스를 흉기 탐지 모델에서 받기 때문에 그쪽 임계값이 바뀌면 결과도 따라 바뀝니다.
- 스무딩 값을 16개 클립에 맞춰 정했기 때문에 다른 영상에서는 다시 맞춰야 할 수 있습니다.
